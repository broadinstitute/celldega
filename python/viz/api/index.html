    • Landscape from a local server: view DegaFiles stored on your own machine.

    Landscape data sources and controls

    Landscape supports spatial DegaFiles and single-cell AnnData Zarr for low dimensional embedding landscapes (UMAP/XY). Choose one expression source:

    import celldega as dega

# Spatial image, centroid, boundary, transcript, and expression files.
spatial = dega.viz.Landscape(
    base_url="https://your-data-host/DegaFiles",
    adata=adata,
    cluster_attr="cell_type",
)

# Cell-level AnnData Zarr with a CSC expression layer.
single_cell = dega.viz.Landscape(
    zarr_url="cells.zarr",
    zarr_layer="counts_csc",
    cluster_attr="cell_type",
    nbhd_edit=True,
)

    Local Zarr paths must be beneath the working directory; the widget starts a local HTTP server. HTTP(S) URLs are passed directly to the browser. Optional adata supplies cell metadata, cluster colors, and UMAP positions in preference to the source's metadata. It does not supply expression to the browser. Match its obs_names to the source cell IDs.

    Argument / trait Purpose
    base_url / base_urls DegaFiles URL or multiple DegaFiles datasets
    zarr_url / zarr_layer Single-cell AnnData Zarr and its CSC expression layer; defaults to Chromium technology
    adata Optional AnnData metadata, palette, and obsm["X_umap"]
    cluster_attr / cell_attr Category used for cluster colors (default "leiden") and cell attributes
    landscape_state "spatial", "umap", or "xy"; the available views depend on the dataset
    xy_genes / xy_scale X/Y genes and "linear" or "log1p" scaling
    adata_sig / gene_signature_url In-memory cell-type means or a separate signature AnnData Zarr for viewport estimates
    nbhd / nbhd_edit Supplied neighborhoods and whether editing is enabled
    gates / selected_cells Named polygons with coordinate-space metadata / current selected cell IDs
    min_zoom / max_zoom Optional zoom limits
    max_tiles_to_view / intermediate_zoom_limit Automatic and on-demand spatial transcript/boundary loading thresholds

    XY and neighborhood selections

    single_cell.set_xy("CD3D", "MS4A1", scale="log1p")
single_cell.landscape_state = "umap"  # requires obsm["X_umap"]

# After selecting clusters or drawing a neighborhood in the browser:
cell_ids = single_cell.get_selected_cells()
selected = single_cell.get_selected_cells(adata)  # copied AnnData subset
polygons = single_cell.nbhd_polygons
single_cell.save_nbhds("neighborhoods.geojson")
single_cell.load_nbhds("neighborhoods.geojson")

    select_nbhd(name) restores a saved neighborhood's view/axes and selects its cells. save_gates, load_gates, and select_gate are equivalent names. Spatial polygons use native tissue coordinates; embedding polygons retain their coordinate-space metadata. Filter polygons["space"] before computing physical tissue areas or distances.

    UMAP/XY viewport cell-type counts are exact. Gene bars estimate expression from matching cell-type signatures; no per-cell expression is fetched on pan/zoom. TRX indicates the summary mode in these views. Selected-gene coloring and XY coordinates read actual expression. See the Landscape guide for signature preparation, selection behavior, and adding aligned H&E to DegaFiles, and File Formats for storage schemas.

    Source: Python widget and methods, browser entry points, and AnnData Zarr reader.

    Widget Classes

    The Clustergram widget accepts a parquet_data argument for efficient initialization. Use Matrix.export_viz_parquet to generate this data from a clustered matrix. Passing a JSON network object is deprecated; pass matrix or parquet_data instead.

    Reusing widgets in notebooks

    When rerunning a notebook cell, give a widget a name if the new instance should replace the previous one of that kind:

    landscape = dega.viz.Landscape(
    base_url="https://your-data-host/DegaFiles",
    name="tissue_overview",
)

    Creating another Landscape named "tissue_overview" closes the previous one. Use different names to keep several Landscapes open. registry_key is an alternative to name; if both are supplied, use the same value.

    Without an explicit key, most widgets coexist. Clustergram uses its Matrix name by default, and Enrich uses "default", so give those widgets distinct names when displaying several instances. Call widget.close() to release a widget when it is no longer needed.

    Source: widget lifecycle.

    Yearbook Selection

    A Yearbook renders a grid of cell "portraits". There are three ways to choose which cells it shows, in increasing order of power:

    1. An explicit id list — cells=["cell_1", "cell_2", ...]. The simplest path: you already know the cells you want.
    2. A back-end selection — selection=.... Accepts a celldega.select.Selection, a JSON-ready selection dict, or a plain id list. This is the recommended way to drive the grid from a Python AnnData object, because it carries the query, sampler, scores, and provenance with the cells. See the select module docs for the full query/sampling algebra.
    3. A stateless front-end query — front_end_query=.... Evaluated in the browser against the dataset's DegaFiles, so it needs only a base_url and no Python AnnData.

    Passing both cells= and selection= is rejected. front_end_query= is independent of those two — when set, the browser computes the cell list itself.

    Front-End Query

    front_end_query is a small dict evaluated entirely in the browser. It is a deliberately narrow counterpart to the Python select module — it supports a single cluster filter and/or a single-gene ranking:

    Query Behavior
    {"cluster": {"attr": "leiden", "value": "8"}} Random cells from cluster 8 (capped at num_rows * num_cols * 10 by default).
    {"gene": "BRCA1"} All cells ranked by BRCA1 expression, highest first.
    {"cluster": {"attr": "leiden", "value": "8"}, "gene": "BRCA1"} Cells in cluster 8, ranked by BRCA1 expression.
    {"gene": "BRCA1", "max_cells": 50} As above, capped at 50 cells. 
    yb = dega.viz.Yearbook(
    base_url="https://path-to-dataset",
    front_end_query={"gene": "BRCA1", "max_cells": 50},
    rows=2,
    cols=2,
)

    Note

    The former query= argument was renamed to front_end_query= to distinguish this stateless browser query from the Python-side celldega.select query module. Passing query= still works but emits a DeprecationWarning.

    Snapshots and reopening from a PNG

    A Snapshot combines a screenshot (raster image of the visualization), a memo, and metadata for reproducibility. snapshot() saves it as a PNG plus a readable .md companion. The PNG carries the memo, data links, constructor options, replay settings and data identity; the source data must remain available. from_png reopens it as an interactive widget:

    saved = landscape.snapshot(
    "Cluster 3 rings the structure.", name="Cluster 3", path="figures/"
)

    In a later cell, after the capture finishes:

    view = dega.viz.from_png(saved.path)  # rebuilds from the recorded links
display(view)                       # restores once it renders
landscape.restore_png(saved.path)    # or restore into a widget already open

    Pass in-memory inputs back, such as from_png(path, matrix=mat) or from_png(path, adata=adata). See Snapshots and Portable Snapshots. The earlier screenshot() spelling remains supported for compatibility.

    Interactive, linkable widgets for Jupyter, and helpers to link and save them.

    Widgets:

    • Landscape: the tissue (image, cells, transcripts, neighborhoods) from DegaFiles or an AnnData Zarr store, or a UMAP of the same cells.
    • Clustergram: an interactive clustered heatmap of a celldega.clust.Matrix.
    • Yearbook: a paged grid of cell portraits, often fed by celldega.select.
    • Composition: category counts or proportions compared across groups.
    • CellCloud / NeighborhoodCloud: 3D orbit views of cells and of neighborhood alpha shapes, for example aligned serial sections.
    • Enrich: Enrichr gene-set enrichment of a gene list, such as a Clustergram's rows.
    • Clerk: an AI tool that reads the linked widgets and answers questions with Claude.
    • Landmark: marks corresponding points across serial sections.

    Linking: spatial_clustergram (a spatial widget beside a Clustergram, with optional enrich and clerk), landscape_yearbook, landscape_yearbook_clustergram, clustergram_enrich, link_clerk and landscape_clerk. Linked widgets share selections: clicking a gene or cluster in a Clustergram colors the Landscape, and cells drawn on a Landscape come back to Python.

    Saving views: snapshot saves a PNG with a memo and the state to recreate it; from_png rebuilds the view from that PNG; load_snapshots reads a folder of them. Widgets report their current view as latest_state; Landscape, Clustergram, Composition and the 3D views also take apply_state to set it from code.

    CellCloud

    Bases: _SpatialWidget

    3D orbit view of cell centroids (replaces Landscape(technology="point-cloud")).

    Renders a pre-built point-cloud DegaFiles directory — cell positions from cell_metadata.parquet (or cell_metadata_<alignment>.parquet when alignment is set), colored by cluster/gene. Build one with celldega.pre.write_point_cloud_dataset.

    Parameters:

    Name Type Description Default
    base_url str or list

    DegaFiles URL(s), as in Landscape.

    		 required
    zarr_url str or Path

    Self-contained AnnData Zarr instead of base_url. X (or zarr_layer) is CSC; obsm['spatial'] holds XYZ positions, with named variants at obsm['spatial_<alignment>']. Original observation IDs retain cell identity. Export with celldega.pre.write_point_cloud_zarr. Local paths use the shared local HTTP server.

    		 required
    zarr_layer str

    CSC expression layer, or "X". Defaults to CSC X or the only CSC layer in the store.

    		 required
    adata AnnData

    Source of cell attributes/metadata (clusters, colors, UMAP). Never used for spatial positions — those come from the DegaFiles — except when use_adata_3d_centroids is set. With zarr_url, positions always come from the store.

    		 required
    alignment str

    Named alignment variant; cell positions are read from cell_metadata_<alignment>.parquet.

    		 required
    cell_size float

    Default cell diameter in microns, assuming centroid coordinates are in microns. Default: 10. The CELL slider multiplies this diameter (0-2x, with 1x at its initial midpoint).

    		 required
    use_adata_3d_centroids bool

    When an adata with obsm["spatial"] is given, render its centroids (obs[z_key] for Z, falling back to 0) instead of the on-disk geometry — to preview a candidate alignment without rewriting DegaFiles. Default: True.

    		 required
    z_key str

    obs column holding the Z coordinate for use_adata_3d_centroids. Default: "Z".

    		 required

    use_adata_3d_centroids writes centroids to a small sidecar file next to base_url and fetches it over HTTP when base_url is a local celldega.viz.get_local_server() address (millions of per-cell centroids don't fit through the widget's comm channel); otherwise it falls back to syncing them through widget state, fine for smaller datasets.

    Example::

    cloud = dega.viz.CellCloud(
    base_url=point_cloud_url,  # from pre.write_point_cloud_dataset
    cluster_attr="cell_type",
    rotation_x=20,
)
cloud

    Link it to a Clustergram with celldega.viz.spatial_clustergram.

    Clerk

    Bases: CelldegaWidget

    Clerk -- Celldega's AI tool for exploring and interpreting its visualizations.

    .. warning:: Experimental. Clerk is a proof of concept: its features, API and saved formats may change between releases, without deprecation.

    Works like Enrich, but instead of the Enrichr API it talks to Claude via the local claude CLI (kernel-side, no API key). The scientist asks free-form questions in a chat box; Celldega bundles the available evidence -- the gene list, pre-fetched Enrichr terms, a captured Landscape raster, and any free-text context -- into a single-shot prompt so Claude reasons only from what it is shown.

    Reads as both a law clerk (gathers evidence, drafts reasoning, the human decides) and a bodega clerk (fetches what you ask for).

    Clerk is standalone and wide by default. Link it to other widgets (which can live in other notebook cells) either from the constructor or via dega.viz.link_clerk::

    clerk = dega.viz.Clerk(landscape=ls, clustergram=cgm, enrich=en)

    Or lay it out with them, linked: as a narrow sidecar column at the end of the row, like Enrich, or full width underneath::

    dega.viz.spatial_clustergram(ls, cgm, clerk=True)                     # sidecar
dega.viz.spatial_clustergram(ls, cgm, clerk=True, clerk_layout="wide")

    Enrichr results Clerk gets are drawn in the conversation, like the Enrich panel: a bar graph of the top terms and a paragraph of the genes tested.

    Parameters:

    Name Type Description Default
    landscape Landscape

    Optional. Link a Landscape; its raster + zoom/pan flow in as image evidence.

    		 required
    clustergram Clustergram

    Optional. Link a Clustergram; selected genes flow into gene_list.

    		 required
    enrich Enrich

    Optional. Remembered for enrichment-term evidence sharing (roadmap).

    		 required
    gene_list list

    Marker / DE genes for the selection.

    		 required
    context_info str

    Free-text context (dataset, cluster id, notes).

    		 required
    model str

    Optional Claude model alias or id (e.g. "opus", "sonnet", "haiku"). Empty inherits the CLI default. A smaller model is cheaper/faster for routine annotation.

    		 required
    effort str

    Reasoning effort, "low" to "max" ("xhigh" in between); empty inherits the CLI default. Higher effort is slower and uses more tokens.

    		 required
    width int

    Widget width in px; 0 (default) means full container width.

    		 required
    name str

    Registry key; creating a new Clerk with the same name closes the old.

    		 required

    snapshots property

    The views Clerk was shown in this conversation, as Snapshots.

    One per widget per capture, named by question: "Q1 Landscape", "Q1 Clustergram" (a later capture for the same question is "Q1.2 Landscape"), with the question as the memo; plus the Snapshots Clerk saved with its screenshot action. They're kept in memory (and written as Snapshot PNGs when you export a report); clerk.snapshots.save(folder) writes them::

    clerk.snapshots.card("Q1 Landscape", landscape=landscape)
landscape.pins = clerk.snapshots

    ask(question, **kwargs)

    Ask a question from Python (bypasses the chat UI). Returns the answer text.

    Unlike the chat box, this blocks until the answer arrives. A cell can't wait for the browser, so this uses the views' latest snapshots (e.g. the last Landscape capture and Clustergram.latest_state) rather than fresh ones.

    cell_types()

    Cell types per cluster: the linked Clustergram's labels and Clerk's proposals.

    One row per cluster that is labeled on the Clustergram (its manual column category) or that Clerk proposed a cell type for:

    • label: the Clustergram's label, and set_by: "you" or "Clerk" (labels you edited after Clerk set them count as yours);
    • clerk_proposal and confidence: Clerk's latest proposal, whether or not it was put on the Clustergram.

    Both are saved with a case (save_conversation, export, which also writes this table as cluster_labels.csv) and come back when it's reopened.

    close()

    Close the conversation's Claude session, then the widget.

    draft_notebook(offer_id=None)

    Write a notebook Clerk suggested (as the panel's Draft notebook button does).

    offer_id picks the suggestion; by default the latest one not yet drafted. Returns the notebook's path, or None if there was nothing to draft.

    export(folder=None, *, title='', adata=None, groupby=None, key='clerk_cell_type', write_h5ad=False, names=None, html=True)

    Save a record of this conversation that you can take with you.

    Writes into folder (default <output_dir>/<title>, e.g. clerk_files/kidney-exploration, or clerk_files/report untitled; a name already taken gets -2, -3..., and the panel says so; the date is in record.json):

    • report.html: the whole conversation as one page. Each screenshot sits under the code that recreates that view (landscape.apply_state(...), cgm.apply_state(...)); Clerk's work and evidence are collapsed.
    • report.ipynb: the same as a notebook, to re-run the code.
    • record.json: everything, machine-readable.
    • screenshots/: each capture as a Celldega screenshot (a PNG carrying the record to reopen its view with dega.viz.from_png).
    • findings.csv: the cell types Clerk proposed.
    • cluster_labels.csv: the cell types per cluster (cell_types): the Clustergram's labels, yours and Clerk's, and Clerk's latest proposals.

    With adata and groupby, the latest cell types are also written into adata.obs[key] (see write_cell_types; a column Clerk wrote before is replaced) and saved as cell_types.csv, plus adata.h5ad with write_h5ad=True.

    open_case(clerk_files=None)

    Reopen a saved Clerk case, to explore it or keep working on it.

    clerk_files is a report folder (from export or the panel's Report button), a saved conversation (.json), or a folder of them such as clerk_files (the default, output_dir), which opens the most recent. Same as Clerk(clerk_files=...).

    dict dict

    run_analysis(which=-1, *, wait=False)
